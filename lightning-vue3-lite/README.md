# Lightning Lite 前端

Lightning Lite 的管理端应用，基于 Vue 3、TypeScript、Vite、Element Plus 和 Pinia，提供设备接入配置、设备管理、数据查询及平台管理页面。

配套后端目录为 `lightning-lite`。本项目需要连接后端服务，前后端应使用相同发布版本。

## 功能范围

- **产品与设备**：产品分类、产品模板、产品、设备及属性绑定。
- **接入配置**：边缘网关、数据点位、传输协议与消息编解码配置。
- **基础数据**：设备标签、建筑区域、单位及单位分类。
- **数据查询**：设备历史数据与告警日志。
- **平台管理**：用户、角色、部门、菜单、字典、通知和个人中心。
- **运维工具**：日志、定时任务、缓存与服务监控、代码生成和系统备份。

页面访问由账号权限及后端菜单配置控制。Lite 不包含能源管理业务页面和可视化大屏编辑器，告警日志查询也不等同于完整的告警规则与场景联动功能。

## Lite 与完整版功能对比

Lightning Lite 聚焦设备接入、管理和数据查询；Lightning 完整版在此基础上提供自动化联动、能源管理和可视化能力。

| 功能 | Lightning Lite | Lightning 完整版 |
| --- | --- | --- |
| 产品分类、产品模板与属性建模 | 包含 | 包含 |
| 设备、网关、数据点位与属性绑定 | 包含 | 包含 |
| 标签、单位与建筑区域管理 | 包含 | 包含 |
| 设备属性下置与分组批量下置 | 包含 | 包含 |
| MQTT 消息接入与自定义编解码 | 包含，需配置 Broker 和编解码插件 | 包含，需配置 Broker 和编解码插件 |
| Modbus TCP、OPC UA、KNX、BACnet、PLC4X 驱动插件源码 | 包含，按需构建安装 | 包含，按需构建安装 |
| 设备实时状态与历史数据查询 | 包含 | 包含 |
| MySQL / InfluxDB 历史存储策略 | 包含 | 包含 |
| 告警日志查询 | 包含 | 包含 |
| 规则场景配置、场景联动与执行记录 | 不包含 | 包含 |
| 可视化自动化流设计、发布与运行管理 | 不包含 | 包含 |
| 能源类型、区域、支路、分项与表具管理 | 不包含 | 包含 |
| 能耗统计与报表 | 不包含 | 包含 |
| 电价策略与碳排放因子配置 | 不包含 | 包含 |
| 可视化项目、图表编辑与大屏预览发布 | 不包含 | 包含 |
| 数字孪生场景编辑、资源管理与运行展示 | 不包含 | 包含 |
| 用户、角色、菜单与权限管理 | 包含 | 包含 |
| 日志、定时任务、代码生成与系统备份 | 包含 | 包含 |

本表按当前版本的业务模块和页面范围整理。“包含”表示提供相应模块；协议适配范围仍需按驱动与现场设备确认。Lite 中保留的告警日志查询不包含完整的告警规则配置与场景联动。前后端、菜单及插件应使用配套版本。

## 环境准备

- Node.js：使用与 Vite 6 及项目依赖兼容的版本，建议从 Node.js 22 环境开始配置；依赖的额外要求以安装时的 `engines` 提示为准。
- Yarn：本文命令使用 Yarn Classic 1.x。
- 浏览器：支持现代 JavaScript 的 Chrome、Edge 或 Firefox。
- 后端：已完成数据库初始化并可以访问的 Lightning Lite 后端服务。

[Vite 6 环境要求](https://v6.vite.dev/guide/#scaffolding-your-first-vite-project)仅说明构建工具本身的要求；完整项目的兼容性还取决于其余依赖。

## 快速开始

在前端根目录 `lightning-vue3-lite` 执行：

```bash
yarn install
yarn dev
```

开发服务器默认地址为 `http://localhost:80`。端口被占用或需要调整时，可运行：

```bash
yarn dev --port 5173
```

以终端实际输出的访问地址为准。登录账号由后端初始化数据和部署者维护。

## 后端代理与环境配置

开发环境默认链路：

```text
浏览器 → /dev-api → http://localhost:8080 → 后端接口
```

后端地址由 [`vite.config.ts`](vite.config.ts) 中的 `baseUrl` 配置；本地后端使用其他地址时，修改该值并重启开发服务器。

| 文件 | 模式 | 默认接口前缀 |
| --- | --- | --- |
| [`.env.development`](.env.development) | 本地开发 | `/dev-api` |
| [`.env.staging`](.env.staging) | 测试构建 | `/stage-api` |
| [`.env.production`](.env.production) | 生产构建 | `/prod-api` |

`VITE_APP_TITLE` 设置页面标题，`VITE_APP_BASE_API` 设置接口请求前缀。`VITE_` 环境变量会进入前端构建产物，不应存放服务端密钥或数据库密码。

## 检查与构建

```bash
# TypeScript 类型检查
yarn typecheck

# 测试环境构建
yarn build:stage

# 生产环境构建
yarn build:prod

# 本地预览构建结果
yarn preview
```

构建输出位于 `dist`。本地预览不提供开发代理，联调生产接口需要相应的代理或服务端部署配置。

## 部署说明

将 `dist` 部署到 Nginx 等静态服务器，并配置：

1. 单页应用路由回退，确保刷新业务页面时可以返回 `index.html`。
2. API 反向代理，将 `/prod-api`（或测试环境的 `/stage-api`）转发到后端，并去掉此前缀。
3. 使用实时数据页面时，按实际请求路径配置 WebSocket 转发。

开发服务器中的代理只在 `yarn dev` 时生效，构建后的静态文件需要由部署服务器提供代理。部署在子路径时，还需同步调整 Vite `base` 及实际路由和资源路径。

## 目录结构

```text

src/views/iot/    物联网业务页面

src/utils/        工具函数

public/           公共静态资源
```

## 常见问题

- **接口报 404 或连接失败**：检查后端状态、`baseUrl`、环境接口前缀和部署代理规则。
- **看不到某个菜单**：检查账号角色权限和后端菜单配置，退出后重新登录。
- **刷新业务页面返回 404**：检查静态服务器的单页应用路由回退。
- **页面有历史菜单但没有对应页面**：检查初始化菜单是否与当前 Lite 版本一致。
